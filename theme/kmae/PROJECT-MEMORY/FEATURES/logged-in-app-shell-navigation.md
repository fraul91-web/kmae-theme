# FEATURE — LOGGED-IN APP SHELL + NAVIGATION

## PURPOSE
Render the authenticated topbar/mobile controls/app wrapper, menu badges, drawer menu, profile dropdown, footer and bottom nav.

## READ FIRST
- `header.php`
- `footer.php`
- `assets/js/theme.js`

## THEN IF NEEDED
- `functions.php::kmae_app_menu_groups()`
- `template-parts/app-menu-panels.php`
- `assets/css/simple-mode/header.css`
- `assets/css/simple-mode/app.css`
- `assets/css/simple-mode/app-shell-dark.css`

## DO NOT LOAD UNLESS RELEVANT
- landing template;
- listing-create CSS;
- plugin DB implementation unless the badge value itself is wrong.

## ENTRY POINTS
All logged-in requests through `get_header()` / `get_footer()`.

## IMPORTANT SYMBOLS
`$kmae_unseen`, `$kmae_own_listing`, `$kmae_nav_active`, `kmae_is_listing_create_nav_context()`, `kmae_app_menu_groups()`, JS drawer/dropdown/bottom-nav handlers.

## DATA USED
Current user name/login/id, request path, post author, plugin counts for unseen activity and active listings.

## FLOW
Header computes state → renders desktop/mobile navigation → logged-in drawer uses menu-group model → JS manages interaction → footer closes app layout and renders bottom nav.

## DEPENDENCIES
`KMAE_Database`, `KMAE_Seller`, `KMAE_Icons`, `KMAE_Pages` are plugin-owned.

## SIDE EFFECTS
UI state only; logout links use WordPress logout URL.

## CHANGE RISKS
- desktop header nav and drawer menu are generated by different code paths;
- unseen count = unread chat (Üzenetek badge only);
- opening tags for `.kmae-app-layout/.kmae-app-content` are in header and closing tags in footer, so layout changes must preserve pairing.

## V2 DIAGNOSTIC ROUTING

**FEATURE:** LOGGED IN APP SHELL NAVIGATION  
**PURPOSE:** Keep diagnosis inside the smallest theme-owned path before crossing any plugin boundary.

**COMMON SYMPTOMS:** shell collapsed; nav active wrong; drawer/profile/footer/bottom nav broken; badge display wrong.

**READ FIRST:** `header.php` state/nav/drawer + `footer.php` app-close/bottom-nav + named handler in `theme.js`; `kmae_app_menu_groups()` only for drawer model.

**EXPECTED FLOW:** auth state → header/app wrapper → page content → footer close → navigation JS.

**CHECKPOINTS:** DOM structure paired? correct nav model? exact handler state? count producer vs render?.

**IF X → GO TO:** desktop active wrong → header; drawer active/badge wrong → menu groups; interaction → theme.js; bad count producer → plugin.

**SEARCH TERMS:** `kmae-app-layout`, `$kmae_nav_active`, `$kmae_own_listing`, `kmae_app_menu_groups`, `kmae-drawer`, `kmae-bottom-nav`.

**DO NOT LOAD UNLESS:** feature backend unless shell symptom proves feature-specific.

**PLUGIN BOUNDARY:** counts/icons/URL resolver are plugin boundaries; shell markup/JS is theme-owned.

**CHANGE RISKS:** desktop nav and drawer use different models; header opens wrappers footer closes them.

**REGRESSION CHECKS:** guest unaffected; logged-in desktop/mobile; own listing; badge zero/positive; drawer/dropdown/footer/bottom nav.

**VERIFICATION STATUS:** VERIFIED theme shell.
