# DEALER-LEADS — Csoportos kereskedői megkeresés

**Állapot:** KÉSZ — mind a 11 fázis (adatréteg, kapcsoló, sugár-egyezés, küldés + levél, cég válasza → chat, lejárat + életciklus, eladói ablak, Értesítések oldal, élő frissítés + csengő, felülvizsgálati javítások, telefonos CSS). Kapcsoló (`kmae_dealer_leads_enabled`, Albira → Beállítások) 2026-10-24 óta BE, élesen.

## Cél
Magánszemély eladó (`KMAE_Auth::is_private_person`) egy aktív hirdetéséhez sugarat (`RADII` 25/50/100/200/0 = egész ország) és célt választ (két FÜGGETLEN jelölő: „Eladnám” `sell` és/vagy „Beszámíttatnám” `tradein`, legalább az egyik; mindkettő = `both`, a cégeknél VAGY); a rendszer a sugáron belüli, felvásárló / beszámító cégeknek (`KMAE_Auth::is_company` + `KMAE_Company::buys_cars` / `accepts_tradein`, koordináta `KMAE_Geo::user_coords` ↔ `listing_coords`, `distance_km`) egyenként megkeresést küld. A cég válasza: „Érdekel” (→ `KMAE_Conversations::create` + rendszerüzenet) vagy „Köszönöm, nem”; válasz nélkül 7 nap után lejár. Megjelenítés: Értesítések oldal (`[kmae_notifications]`, `KMAE_Shortcodes::notifications`), nem az Üzenetek lista.

## Tábla `{prefix}kmae_dealer_leads`
- Létrehozás: `KMAE_Dealer_Leads::maybe_create()` a `KMAE_Activator::maybe_upgrade`-ből (saját séma-opció `kmae_dealer_leads_schema`, hiba esetén transient `kmae_dealer_leads_retry` 1 óra), és `create_table()` a `create_tables`-ből. **KMAE_VERSION-t ne emeld miatta.** Séma-változásnál `SCHEMA_VERSION` emelés; a `maybe_create()` addig újrafuttatja a `dbDelta`-t, amíg a tárolt verzió != `SCHEMA_VERSION` (meglévő táblához az új oszlopot a dbDelta adja). Séma **2** = `dealer_price`; a `create_table()` a dbDelta után `SHOW COLUMNS … LIKE 'dealer_price'`-szal ellenőriz, ha az oszlop hiányzik, a séma-opció marad régi + 1 órás újrapróbálás-zár.
- Oszlopok: `id`, `listing_id`, `seller_id`, `dealer_id`, `purpose` (varchar(16), `sell|tradein|both` — a soron a cég TÉNYLEGES célja = az eladó választása ∩ a cég jelölői; séma-változás nem kellett), `status`, `token` char(32), `batch_id` char(32) (egy „Elküldöm” kattintás), `distance_km` decimal(6,1) NULL, `dealer_price` bigint unsigned NULL (**kereskedői ár Ft-ban**, küldésenként: a batch minden során ugyanaz; későbbi küldés más árral = új batch új árral, a korábbi cégeké marad; a hirdetés nyilvános ára nem változik), `conversation_id` NULL, `listing_title` (snapshot, törölt hirdetéshez), `created_at`, `expires_at`, `responded_at` NULL, `updated_at` — minden időpont **UTC** (`gmdate`), nem a MySQL órája.
- Kulcsok: **UNIQUE (listing_id, dealer_id)** = egy cég egy hirdetést SOHA nem kap kétszer (bármi lett a vége); UNIQUE token; (dealer_id,status), (seller_id,listing_id), (status,expires_at), batch_id.
- Sorok nem törlődnek (előzmény) — kivétel: admin „Újraindítás tiszta lappal” (`delete_for_listing`). Új listing_id (törölt + újra feltöltött autó) újra küldhető.

## Állapotok
`pending` → `interested` | `declined` | `expired` (cron) | `cancelled` (hirdetés törlés/lezárás). Átmenet csak `pending`-ből és (válasznál) csak le nem járt sorból: `UPDATE … WHERE id=%d AND status='pending' AND expires_at > now` → `rows_affected === 1` (dupla kattintás ellen).

## API (`includes/class-kmae-dealer-leads.php`)
- `is_enabled()` — opció `kmae_dealer_leads_enabled` (Albira → Beállítások checkbox) VAGY `manage_options`. **Kapcsoló KI + admin eladó:** a `match()` csak `manage_options` jogú cégeket tart meg (admin→admin próba megy; valódi cég nem kaphat olyat, amit az Értesítések oldalon nem lát / nem tud megválaszolni) — az előnézet és a küldés ugyanazt a `match()`-et használja, a számok egyeznek.
- `insert_batch($listing_id, $seller_id, $purpose, array $dealer_id_to_km, $title = null, $price = null)` (`$purpose` = sztring `sell|tradein|both` az egész batchre, VAGY `dealer_id => cél` térkép soronkénti tényleges céllal; a térképből hiányzó / érvénytelen célú cég kimarad; a `$price` Ft, a batch minden sorára; null/≤0 = NULL, régi hívások változatlanok) → az ÚJ sorok (INSERT IGNORE, 200-as darabok, saját magát kihagyja); cím = `KMAE_Vehicle::get_display_title`.
- `mark_interested($id, $conversation_id = 0)`, `set_conversation($id, $conv_id)` (ha a chat a „lefoglalás” után jön létre), `mark_declined($id)` → bool.
- `expire_due($now = null, $limit = 500)`, `cancel_for_listing($listing_id)` → a ténylegesen váltott id-k. **`ready()` őr** (hiányzó tábla / séma még nem kész → SQL nélkül 0 / `array()`): `bell_count`, `count_pending_for_dealer`, `on_listing_ended`, `cancel_for_dealer`, `delete_for_listing`, `list_for_dealer`, `list_for_seller`, `expire_due` (az Értesítések ujjlenyomat is ezeken át megy).
- 6. fázis: `on_listing_ended($listing_id)` (= `cancel_for_listing` + NÉMA `KMAE_Live_Signal::bump` az érintett cégeknek), `cancel_for_dealer($dealer_id)` (fiók-törlés, cég oldal: pending → cancelled, sorok maradnak; néma bump az érintett eladóknak), `delete_for_listing($listing_id)` (admin tiszta lap: DELETE, visszaadja az érintett user ID-ket a hívó bump-jához), `run_expire_cron()` (cron-kezelő: `expire_due` 500-asával + 1 néma bump cégeknek ÉS eladóknak; levél/push nincs), `parse_price($raw)` (szóköz/nbsp/pont kiszedve, csak számjegy → int|null).
- `get($id)`, `get_by_token($token)` (formátum-ellenőrzés `is_token`), `contacted_dealer_ids($listing_id)`, `counts_for_listing($listing_id)` (pending/interested/declined/expired/cancelled/total, nyers állapot), `list_for_dealer($dealer_id, $limit = 50, $statuses = [])`, `list_for_seller($seller_id)` (hirdetésenként: counts, last_sent_at, `dealer_price` = a legutóbbi küldésé [a sorok legújabb elöl], leads), `count_pending_for_dealer($dealer_id)` (le nem járt pending).
- `can_start($listing_id, $user_id)` → `true|WP_Error` (magyar üzenet; kódok: `dealer_leads_disabled|no_listing|not_owner|not_private|inactive|reserved|no_location`). Feltétel: `is_enabled()`, `kmae_listing`, szerző = user, `KMAE_Auth::is_private_person`, `post_status=publish` ÉS `KMAE_Meta::get_status` = `active`, `KMAE_Chat_Offers::listing_state` NEM `reserved`/`sold`/`lapsed` (Foglalt hirdetéshez nincs új megkeresés; `reopened` mehet), `KMAE_Geo::listing_coords` van.
- `effective_purpose($chosen, $buys, $tradein)` → `sell|tradein|both|null` (a választás és a cég jelölőinek metszete; null = nem felel meg).
- `match($listing_id, $radius_km, $purpose = null)` → `['radius','purpose','in_radius','matching','contacted','new','new_dealers'=>[id=>km|null],'new_dealer_purposes'=>[id=>sell|tradein|both] (new_dealers sorrendjében; cél nélkül üres),'contacted_dealers'=>[id=>km|null]]` vagy `WP_Error` (`dealer_leads_bad_radius|bad_purpose|no_listing|no_location` — utóbbi csak sugárnál; 0 = egész ország koordináta nélkül is megy). Egyetlen `WP_User_Query` (`kmae_company_buys` VAGY `kmae_company_tradein` = '1') + `update_meta_cache('user')`, a többi PHP. Kizár: az eladót, sugárnál a telephely-koordináta nélküli céget (0 = bent, távolság `null`, a lista végén), tiltást mindkét irányban (`KMAE_User_Blocks`: eladó tiltja a céget VAGY a cég az eladót), nem céges fiókot (`KMAE_Auth::is_company` — szándékosan a szűrők UTÁN, felhasználónként 1 SQL). A koordináta `KMAE_Settlements::coords(county, city)` közvetlenül (nem `KMAE_Geo::user_coords`, annak `is_company`-ja szűrés előtt futna). `sell` → buys, `tradein` → tradein jelölő, `both` → buys VAGY tradein (egyesítés, nem metszet); `in_radius` = bármelyik jelölővel a sugáron belül. Rendezés: távolság növekvő, azonos/null → ID.
- Sor-formátum: típusos tömb (`row()`); UI-ba user/lead ID helyett a `token` menjen.

## Végpontok (4. fázis)
`KMAE_Dealer_Leads::init()` (a `KMAE_Plugin::run` hívja) → csak belépve: `wp_ajax_kmae_dealer_leads_preview`, `wp_ajax_kmae_dealer_leads_send` (admin-ajax, a Cloudflare nem cache-eli). POST, mezők: `nonce` (action `kmae_dealer_leads` = `NONCE`, `KMAE_Dealer_Leads::nonce()`), `listing_id`, `radius` (a `RADII` egyike, szövegként is), `purpose` (`sell|tradein|both`; a kliens a két független kapcsolóból képzi: csak Eladnám = `sell`, csak Beszámíttatnám = `tradein`, mindkettő = `both`; semmi = hiba; előnézetnél elhagyható = csak sugár), **`price`** (CSAK a `send`-nél, KÖTELEZŐ: kereskedői ár egész Ft-ban; szóköz/pont/nbsp-s ezres-tagolás megengedett, minden más nem-számjegy hiba; `PRICE_MIN` 50 000 ≤ ár ≤ `PRICE_MAX` 500 000 000; az előnézetnek nem kell).
- Kliens-adat (8. fázis): `KMAE_Dealer_Leads::client_config($listing_id)` → `{ajaxUrl, nonce, listingId, available, reason, actions:{preview,send}, radii:[{value,label}], purposes:[{value,label}] (továbbra is csak `sell` + `tradein`: az UI ebből két független kapcsolót rajzol, a `both` kliens-oldali kombináció), ttlDays, priceMin, priceMax, listingPrice}` (`listingPrice` = a hirdetés nyilvános ára Ft-ban a puha tipphez, `KMAE_Seller::get_public_price`; „Ajánlatot vár” hirdetésnél `null`) (a belépett userre; `reason` = a `can_start` magyar hibája). Cég-azonosító / név nincs benne.
- **preview** → `can_start` + `match` → `success: {in_radius, matching, contacted, new, all_sent}` (`all_sent` = matching > 0 és new = 0). Csak számok, soha cég-ID/név. Nem ír.
- **send** → cél kötelező → ár kötelező (`dealer_leads_bad_price`: „Add meg, mennyiért adnád az autót kereskedőnek.”) → `can_start` → `GET_LOCK('kmae_dealer_leads_<listing>', 5)` → FRISS `match()` (a kliens számait nem hisszük) → `insert_batch(…, $price)` → `RELEASE_LOCK` → `success: {sent, already, total_matching, all_sent, message}` (`already` = a küldés előtt már megkeresett megfelelő cégek; `message` magyar, kész felirat: „Elküldtük N cégnek…” / „…már minden megfelelő cégnek elküldted…” / „Ebben a körzetben most nincs megfelelő cég…”). Dupla kattintás / két fül: a második `sent: 0, all_sent: true` (a UNIQUE kulcs zár nélkül is véd). 0 megfelelő cég = siker `sent 0, all_sent false`.
- Hiba → `error: {code, message}` (magyar): `dealer_leads_login|dealer_leads_nonce` 403; a többi 400: a `can_start`/`match` kódjai + `dealer_leads_bad_purpose` („Válassz legalább egyet: eladnád vagy beszámíttatnád az autót.”), `dealer_leads_bad_price`, `dealer_leads_busy` (a zár 5 mp alatt nem jött meg), `dealer_leads_failed` (volt új cég, de 0 sor jött létre).
- Értesítés (csak az ÚJ sorok, cégenként külön, egymásról nem tudnak): azonnal EGY `KMAE_Live_Signal::bump(új dealer ID-k, note)` (push „Új autó-megkeresés érkezett”, törzs „<cím> — 7 napig válaszolhattok.”, url = Értesítések oldal, tag `kmae-dealer-lead-<listing>`; a levelet kikapcsoló cég is kapja); a levél a `shutdown` 90-en épül (`send_queued_notifications`: előbb `KMAE_Perf::finish_response()`, `cache_users`, a `get_swipe_subtitle` hirdetésenként egyszer), a kiküldés a `KMAE_Perf` sorából (shutdown 110) → a válasz nem vár a levelekre. Levél: `KMAE_Notifications::notify_dealer_lead` (key `dealer_lead`, „Cégeknek” csoport, csak céges fióknak ÉS bekapcsolt funkciónál [`is_enabled()`] látszik a Beállításokban; a mentett kapcsolók kikapcsolt funkciónál is megmaradnak — a `mail_catalog_keys(0)` mindig a teljes lista), tárgy „Új autó-megkeresés: <cím>”, tone `info`, a bevezető sor cél szerint (eladná / beszámíttatná / `both`: „Egy magánszemély eladná vagy beszámíttatná az autóját…”), a kártyában az autó-blokk után az ár-sor („Kereskedőnek ennyiért adná: 2 450 000 Ft” [`sell` és `both`] / beszámításnál „Beszámításra ennyiért adná: …”; `KMAE_Vehicle::format_value`; régi, ár nélküli sornál kimarad) és a megjegyzés „Ne utasítsátok el csak az ár vagy a képek miatt. Ha az autó érdekes, nyomjatok az Érdekel gombra, és alkudjatok a chatben.”, gomb „Megnézem” → `KMAE_Dealer_Leads::lead_url($token)` = `/ertesitesek/?kmae_lead=<token>`. Eladó neve / telefonja / e-mailje nincs benne. 100+ cégnél a háttér-kiküldés soros (SMTP-nként ~0,5 s) — ha a tárhely `max_execution_time` szűk, a 6. fázisban cron-kötegre bontható.

## Válasz (5. fázis) — „Érdekel” / „Köszönöm, nem”
Űrlap (az Értesítések sablonja, 7. fázis): `<form method="post" action="<?php echo esc_url( KMAE_Dealer_Leads::answer_form_action() ); ?>">` (= `admin-post.php`) + `KMAE_Dealer_Leads::answer_form_fields( $token )` (kiírja és visszaadja: rejtett `action=kmae_dealer_lead_answer`, `token`, `wp_nonce_field('kmae_dealer_lead_answer')` → `_wpnonce`; 2. paraméter `false` = csak visszaadja) + két gomb `name="answer"` value `interested` / `declined`.
- Hook: `admin_post_kmae_dealer_lead_answer` → `handle_answer` (nonce → `answer($token, $answer, user)`), `admin_post_nopriv_…` → `handle_answer_nopriv` → `KMAE_Auth::login_url( lead_url($token) )` (rossz tokennél az Értesítések oldalra vissza).
- `answer()` sorrend: válasz-érték → `get_by_token` + `dealer_id === user` → `is_enabled()` (mindkét válasznál) → `GET_LOCK('kmae_dealer_lead_<id>', 5)` → friss sor → állapot:
  - már `interested` → a chatjére visz (bármelyik gombnál; ha a `conversation_id` még üres = félbeszakadt kérés, a befejezés ELŐTT lefut az e-mail kapu [`lead_unverified`] és a `can_answer_interested` [`lead_unavailable`] — hibánál átirányítás, a sor `interested` marad, nincs visszaállítás);
  - `declined` → ismételt „nem” = ugyanaz a siker, „Érdekel” = `lead_answered`; `expired` vagy `pending` + lejárt `expires_at` → `lead_expired`; `cancelled` → `lead_unavailable`.
  - **„nem”**: `mark_declined` → nincs chat/üzenet/levél; az eladónak NÉMA `KMAE_Live_Signal::bump([seller])` (note nélkül = csak jelzőfájl, push nincs; a 9. fázis Értesítések-fingerprintje ebből frissülhet). A hirdetés állapotát nem nézi (törölt hirdetésnél is mehet).
  - **„Érdekel”**: e-mail kapu `KMAE_Auth::should_gate_for_verification(cég)` (mint az „Üzenet küldése”) → `can_answer_interested($lead)` (a hirdetés még az eladóé, `publish` + `active`, `listing_state` nem `reserved|sold|lapsed`, nincs tiltás egyik irányban sem — a `can_start` az eladót nézi, ez a cég oldala) → `mark_interested` (a válasz „lefoglalása”; ha nem sikerül: a friss sor szerinti állapot-ág) → `KMAE_Conversations::create(listing, cég, eladó)` (a cég = VEVŐ; meglévő chatjét visszaadja → újrahasznosítva) → ha még nincs: rendszerüzenet `KMAE_Chat_Offers::post_system_message(chat, cég, szöveg, 'dealer_lead:<lead id>')` (a cég nevében → az eladó jelvény + levél + push a `kmae_conversation_message_created`-en; a `save_message` a vevőnek beírja a `_kmae_browse_contacted`-et) → `set_conversation` → átirányítás `KMAE_Pages::conversation_thread_url`.
  - Szöveg (`interest_text`): sell „{Cégnév} kereskedés érdeklődik az autód iránt. Írjatok egymásnak itt a chatben.”, tradein „… iránt, beszámításra. Írjatok …”, both „{Cégnév} kereskedés érdeklődik az autód iránt (eladás vagy beszámítás). Írjatok egymásnak itt a chatben.”; cégnév `KMAE_Company::get_company_name` (üres → „Egy kereskedés …”). Az Üzenetek lista csak üzenetes chatet mutat → ez az üzenet teszi láthatóvá mindkét félnek (a cégnél az előnézet „Te: …”, mint minden saját rendszerüzenetnél).
  - Levél/push: `KMAE_Chat_Offers::message_kind` = `dealer_lead` → levél tárgy „Egy kereskedés érdeklődik az autód iránt” (cheer manó, gomb a chatre, mail kulcs `message`), push cím ugyanez, törzs „<hirdetés>: nézd meg a chatben.” (`KMAE_Live_Signal::text_for`).
  - **Meglévő, ZÁRT chat (döntés):** a `create()` a meglévő chatet státusztól függetlenül adja vissza, a `save_message` zárt chatbe nem ír → a `finish_interested()` nem küld üzenetet, a sort `interested` + `conversation_id` = a zárt chat állapotban hagyja (nincs `lead_failed`-hurok / pending-re visszaállítás), és a (olvasható) chatre irányít; a cég kártyáján „Chat megnyitása”.
  - **Visszaállítás (döntés):** ha a `create()` hibázik vagy a rendszerüzenet nem menthető → `error_log` + a sor őrzött UPDATE-tel (`WHERE id = %d AND status = 'interested'`) vissza `pending`-re (`responded_at`, `conversation_id` NULL), így a cég újrapróbálhatja; egy esetleg létrejött üres chat-sor marad (nem látszik, újrapróbáláskor újrahasznosul). A `conversation_id` csak az üzenet UTÁN íródik be; ismételt futás nem küld második üzenetet (`has_interest_message` a kulcsra).
- Átirányítás: siker „Érdekel” → a chat; siker „nem” → `notifications_url()` + `kmae_success=lead_declined`; hiba → `notifications_url()` + `kmae_error=<kulcs>` (`answer_error_url`, a token nem kerül az URL-be).
- **Hibakulcsok (a 7. fázis magyar szövege kell hozzájuk):** `lead_forbidden` (rossz/hiányzó nonce, ismeretlen token, nem ennek a cégnek szól, rossz válasz-érték), `lead_expired` (lejárt), `lead_answered` („nem” után „Érdekel”), `lead_unavailable` (a hirdetés törölt / nem aktív / Foglalt / eladott / lezárt, tiltás van, a megkeresést visszavonták, vagy a funkció ki van kapcsolva), `lead_unverified` (a cég e-mail címe nincs megerősítve — az „Üzenet küldése” kapuja; a szerződésen felüli kulcs), `lead_failed` (a chat nem jött létre / a zár foglalt — próbálja újra). Siker: `lead_declined`.

- Háttér-levélküldés: egyenként, `shutdown`-on (változatlan, a 4. fázis megjegyzése).
